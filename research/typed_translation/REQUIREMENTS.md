# Typed translation: frozen requirements

`AuthorityEffect: None.`

This file is metatheory apparatus.  It fixes the question, the finite carrier,
the translation candidates, the removal experiment, the two common measures,
and every fairness hazard before implementation.  It is committed with
`PREDICTIONS.md` and with no other file in this tree.  Neither frozen file may
be edited after that commit.

The experiment may read repository sources only through a manifest whose
snapshot is an exact forty-lowercase-hexadecimal commit that is an ancestor of
the experiment's HEAD.  The implementation has its own kernel and imports no
module from another research tree or from the sealed package.  Vendored source
values are data, not executable imports.

  profile observations differ; score every frozen boundary-dependence row
  after mechanical removal.
- **Admitted primitive:** the sealed unary form and its admitted instances and

- **Derived definition:** both bounded carriers, event-kind preservation,

- **Proved theorem:** only declarations present in the tree's Lean axiom
  inventory.  In particular, the memoryless-rule obstruction and the

- **Deterministic computation:** every enumerated history, candidate verdict,

## 2. The two carriers

### 2.1 Sealed-side bounded carrier

The source carrier is the full replay-closed prefix space generated by these
eight distinct events, each used at most once:

1. `Supply("d0")`;
2. `AdmitDatum("d0")`;
3. `Supply("d1")`;
4. `AdmitDatum("d1")`;
5. `AdmitForm(1)`;
6. `AdmitInst(0, (0,))`;
7. `AdmitInst(0, (1,))`;
8. `AdmitRuleAll(0)`.

An event may be appended exactly when the source replay rule accepts it.
Admission of datum `di` additionally requires its supply earlier in the
history.  An instance requires the unary form and its datum.  The rule requires
the form.  The enumerator retains every valid prefix and every valid ordering;
it does not quotient histories that replay to the same state.  An independent
unpruned permutation-of-subsets census must equal the primary enumerator.

The resulting state retains, separately, admitted data, the unary form,
instances, and the rule.  For datum `i`, the one declared profile bit is

`profile(i) = rule_present OR instance_i_present`.

The compared task exists when both data are admitted and is satisfied exactly
when `profile(0) != profile(1)`.  The `OR` is a projected observation only.
The instance set, rule bit, events, and history remain separate fields; no
claim of state-level conflation follows from equality of profile bits.

### 2.2 Boundary-side typed carrier

The target is a bounded deep-address carrier.  A mark has a presentation label
and a nonempty binary address.  Address bit zero is the outer side.  The next
two bits are a tag.  The four tags are fixed before enumeration:

| tag | role |
|---|---|
| `00` | retained datum mark |
| `01` | unary-form witness |
| `10` | instance or rule-compensation witness |
| `11` | uniform-rule witness |

The direct address family uses `(side, tag[0], tag[1])`; the complemented
family replaces only `side` by `1 - side`.  Both families are candidates.
Labels record provenance for decoding but are forgotten by the default
boundary key.  That distinction is load-bearing: provenance remains in the
carrier and history even when one observation forgets it.

For a source state, the canonical marker set contains:

- the retained datum mark on its coded side for each admitted datum;
- both side copies of the form tag when the unary form is admitted;
- the side-`i` instance tag labelled `inst_i` when instance `i` is admitted;
- both side copies of the rule tag when the rule is admitted;
- when the rule and instance `i` are both admitted, one compensation mark with
  the instance tag on side `1 - i`, labelled `comp_i`.

This set is monotone under every accepted source admission.  The compensation
marks make the unlabeled address multiset outer-symmetric whenever the sealed
profiles are equal, including when an instance is admitted after the rule.

The typed boundary subcarrier is defined structurally, without reference to a
candidate: marker labels must come from the fixed role census above, their
addresses must match the fixed role/side relation, form and rule roles occur in
complete side-pairs, and a compensation role occurs exactly with its named
rule-plus-instance antecedent.  Every structurally valid typed state is in the
backward domain.  It is not selected after observing candidate results.

The nearby refusal shell is also candidate-independent: for every typed state,
delete one mark; add one allowed or one unknown mark; change one label; or flip
one address bit.  Deduplicate by the complete raw state.  Every shell member
not itself typed must receive a named refusal from the backward decoder.  The
shell is reported in full; it is not counted as a successful global map.

The permitted-renaming candidate decides whether mark permutations, the outer
side exchange, and the two tag-level exchanges are available, and whether
labels enter the key.  The task compares the two retained datum marks and is
satisfied exactly when no permitted automorphism carries one to the other.

## 3. Typed events and histories

A typed transaction has kind `PRESENTATION` or `ADMISSION` and expands to raw
events of the carrier it targets.

- A source presentation maps to exactly one target presentation and no
  admission.
- A source admission maps to one target admission transaction containing at
  least one raw target admission.
- If `synthetic_supply` is enabled, that admission transaction may also contain
  exactly one administrative presentation immediately before each raw target
  admission whose label has not already been presented.  Every such
  presentation is counted and reported.  If the coordinate is disabled, none
  may be inserted.
- No presentation transaction may contain an admission, and no admission
  transaction may contain an event other than its admissions and their paired
  administrative presentations.
- The backward map consumes the typed transactions, not an invented mutation
  of final state.  A boundary admission transaction must decode to at least one
  source admission or receive a named refusal.

For every valid source history `h`, forward history preservation means

`replay_boundary(translate_history(h)) == encode_state(replay_sealed(h))`.

Backward preservation means both

`decode_state(replay_boundary(translate_history(h))) == replay_sealed(h)`

and

`replay_sealed(decode_history(translate_history(h))) == replay_sealed(h)`.

For every structurally typed boundary state, encoding after decoding must
return the same complete raw state.  The experiment claims no recovery of the
original ordering when two histories replay to the same state; it claims the
commuting replay equations above and nothing stronger.

## 4. Candidate space

Every candidate is one point of this Cartesian product, in the order shown:

| coordinate | values |
|---|---|
| `event_context` | `memoryless`, `state_sensitive` |
| `synthetic_supply` | `false`, `true` |
| `outer_exchange` | `false`, `true` |
| `mark_permutations` | `false`, `true` |
| `keep_labels` | `false`, `true` |
| `tag_levels_named` | `false`, `true` |
| `address_family` | `direct`, `complemented` |

There are therefore 128 declared candidates.  No candidate is pruned.  A
second product enumerator must reproduce the same 128 canonical coordinate
tuples and ordering.  Every valid candidate, including every tied candidate,
is retained and grouped only by its complete computed behavior record.

`memoryless` emits a fixed role block for each source admission kind.
`state_sensitive` emits the difference between the canonical marker sets of
the before and after states.  State inspection is one priced capability; it is
not smuggled into the memoryless case.  Cost distortion is never an acceptance
filter.  A candidate first passes or fails tasks, event kinds, replay,
round-trip decoding, and shell refusal; its cost is computed afterward.

## 5. The two measures, literally shared

Both carriers' raw events are classified by the same two total functions:

- `mu1(trace)`: the number of raw state-changing admission events in `trace`;
- `mu2(trace)`: the total number of raw presentation and admission events in
  `trace`.

The implementation must define each measure once over a common raw-event-kind
protocol and call that same function for source and target traces.  There is no
source `mu1`, target `mu1`, source `mu2`, or target `mu2`.  A test must fail if
the result record names separate implementations.

For each history and direction, additive distortion is `target - source`.
Multiplicative distortion is a reduced rational when the source cost is
positive and is `ZERO_BASE` otherwise.  The receipt reports the complete
per-history table, minima, maxima, and witnesses.  Exact preservation means
zero additive distortion on every history for both measures.  A bound is a
computed maximum over this declared history space, not a general theorem.

The price to *state* a translation is reported separately as the number and
names of non-default semantic capabilities it uses, including state inspection
and administrative presentation.  That statement price is not added to either
trace measure.

## 6. Preservation verdict

A candidate is a bounded typed map only if all of these are true over the
complete declared spaces:

1. **Tasks:** the sealed profile task and boundary automorphism task agree at
   every valid source history and every decoded typed boundary state.
2. **Accepted events:** every transaction obeys section 3's kind rules and all
   expanded raw histories replay without refusal.
3. **Histories:** all three replay/round-trip equations in section 3 hold.
4. **Carrier:** every separately retained source field decodes exactly, and
   every typed boundary state re-encodes exactly.
5. **Refusal shell:** every non-typed shell state is rejected with one of the
   frozen refusal codes; no unknown state is silently truncated.
6. **Costs:** both common measures are total and their distortion is reported.
   Zero distortion is a separate, stronger verdict and is not required for a
   priced map.

The outcome vocabulary is `MAP_WITH_PRICE`, `PROVED_EXACT_COST_OBSTRUCTION`,
or `OPEN_AT_BOUND`.  A priced map and a proof that exact cost is impossible may
both be reported, with their scopes kept separate.

## 7. Mechanical removal experiment

The vendored dependence population is every `boundary_dependence` entry in
the eight frozen boundary receipts: Challenges 0 through 5 and continuation
stages 1 and 2.  Object-valued maps contribute one row per property in source
order; the final string contributes one row.  The expected population is 37.
An independently counted vendored census must agree or the experiment is VOID.

Each executable carrier record has a top-level `boundary` field and other
fields.  Removal is exactly

`{key: value for key, value in record.items() if key != "boundary"}`.

It may not enumerate fields to keep.  A test compares the source and projected
key sets and requires their symmetric difference to be exactly `{"boundary"}`
for every record.  Nested side, address, reading, name, reflection, placement,
and level-exchange data live only under that field.  Marks, provenance labels,
event kinds, histories, finite counters, and generic algorithms remain outside
it.

Each row below is frozen to a nonempty tuple of executable probe identifiers.
A probe returns a JSON value or `NOT_FORMULATED`.  It is evaluated on the full
record and again on the projected record.  A probe survives iff both values are
JSON-equal.  It depends iff the projected value is `NOT_FORMULATED` or differs.
A row is `INDEPENDENT` when every probe survives, `DEPENDENT` when none does,
and `MIXED` otherwise.  No prose token decides the actual class.

The hand-written claim is separately parsed into `INDEPENDENT`, `DEPENDENT`,
or `MIXED`; an unclassified sentence is a gate failure.  A hit is exact class
equality.  Every miss is named with stage, row id, subject, claimed class,
actual class, and each before/after probe value.

## 8. Fairness hazards and mandatory guards

| hazard | rigging direction | guard fixed before code |
|---|---|---|
| translating only already-matching states | existence | full replay-closed source prefixes, structural typed boundary domain, and nearby refusal shell are candidate-independent |
| strengthening to one raw target admission per source admission | obstruction | admission transactions may contain any positive finite block; every raw admission is priced |
| permitting hidden state inspection | existence | `memoryless` and `state_sensitive` are separate coordinates; inspection is named in statement price |
| requiring memorylessness without justification | obstruction | both modes are enumerated; the Lean memoryless obstruction is reported only for that subspace |
| letting distortion absorb a failed clause | existence | distortion is computed after the four preservation verdicts and never decides validity |
| requiring exact cost before looking | obstruction | priced maps remain eligible; exact cost is a separate stronger verdict |
| using presentation labels as free internal identity | existence | labels are forgotten by default; `keep_labels=true` is separately enumerated and priced by behavior |
| demanding presentation labels survive | obstruction | source tokens and boundary labels remain provenance fields, but task equality uses declared observations and permitted renamings |
| choosing renamings to fit the answer | either | the complete Boolean renaming product is fixed here and enumerated |
| silently dropping a source field in projection | either | projection drops exactly the one top-level `boundary` key; key-set equality is tested at every record |
| scoring dependence from prose words | either | prose parsing supplies only the claimed class; actual class comes only from before/after probe values |
| grouping a mixed subject into one convenient Boolean | either | the 37 row-to-probe tuples above are frozen and every component is reported |
| a vacuous enumeration | either | exact candidate count 128, exact dependence count 37, nonempty history census, shell census, and independent cross-checks |
| pruning hides a tied candidate | either | no pruning; every tied complete behavior record retained |
| numbers in prose drift | either | prose uses named receipt fields; any literal result is bound by a dedicated verifier |
| source values drift | either | exact-commit Git-blob SHA-256 manifest plus vendored-value digest and ancestry checks |

## 9. Required artifacts and gates

The build must add, at minimum: an exact source manifest; vendored dependence
data; a typed Python kernel; a deterministic runner and JSON receipt; tests;
strict typing; a dual 95% fresh coverage gate; a frozen-hash/pin verifier;
source-isolation and no-cross-tree-import checks; a Lean package and axiom
receipt; `STATUS.md`, `CLAIM_LEDGER.md`, `FINDINGS.md`, and `MANUAL.md`.

The research workflow registration must run pins, an asserted nonzero exact
test count, fresh line and branch coverage, deterministic receipt replay and
diff, prose binding, and strict typing.  The Lean verifier may remain a manual
receipt only if the workflow says so explicitly.  Every new gate requires one
minimal reversible injection row in `MANUAL.md`, with the failing command,
diagnostic, direct exit status, reversal, and recovered exit status.  No pin or
receipt is regenerated while an injection is live.

The final report must name the commit order, both frozen hashes, every scored
prediction, the outcome in both directions, the map's distortion or the exact
obstruction witness, every removal-map miss, and the exact battery summaries.
