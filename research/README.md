# Research trees: what runs where

AuthorityEffect: None.  This file states, once, which research trees the
written workflow enumerates and which are local receipts only, and which
verifier files are hand copies of one another.  The table of trees is
generated by `python ci/research_index.py --write`;
`tests/test_research_index.py` fails when a tree is added, removed, or
registered in the workflow without it, and
`research/estate_honesty/audit_estate.py` parses it.  The rest of this file
is written by hand.

Hosted CI is permanently disabled by author decision. Every receipt is local;
"workflow" below means the tree is enumerated by the written contract in
`.github/workflows/verify.yml`, whose gate-11 commands are run locally.
The 2026-08-21 incident recorded in
`CLAUDE.md` — five failing research tests under a green rollup — is why the
distinction is written down.

The Lean receipts are produced by local compilation. The written Lean contract
explicitly includes `second_nofirst` and `typed_translation`; the other listed
research Lean builds are invoked separately. `python ci/research_index.py --show`
prints each tree's entry points, test locations, Lean files, and the trees that
require it or name its paths.

`second` is listed as a local receipt: no workflow step runs anything of its
own, though gate 11 runs the rungs' pin verifiers, which hash its `SEED.md`.
`research/estate_honesty/audit_estate.py` counts it as wired.

The status column records the dated parking decisions in
`ci/research_index.py`. A blank cell makes no activity claim. On 2026-09-20,
`admit_leftover`, `dynamics_step` and `g1_local_class` were marked parked after
checking gate registration, package requires, Python imports and test consumers.
Their files stay in place and their local verifiers remain available. This mark
does not claim that those verifiers were rerun or passed.

The three other proposed candidates stay unmarked: `family_embedding`,
`observer_visibility` and `s9_obligations` have root index tests that read their
Lean layout. The first and last also have explicit build-recipe entries.

live in the others until carried by hand (the primed-name report parser was
one such defect).  The copies to touch on a defect:

*Narrowed 2026-09-18.*  The lists above were typed by hand and are not the
whole population.  The primed-name parser defect they cite was still standing
in four `verify_lean.py` copies the list omits (`higher_order_diagonalization`,
`iso_sound_lean`, `seventh_constructor`, `twin_pricing`) and in two files no
list covers (`exchange_coefficients/verify.py`,
`admission_sign_shadow/verify_frozen_compatibility.py`).  Two tools give the
population rather than a checklist, and are the ones to read before touching
copies on a defect: `python research/house_diff.py --families` finds every
copy of `verify_sources.py`, `verify_lean.py`, `verify_pins.py`,
`test_forbidden.py` and `check_coverage.py` under `research/` and groups them
by bytes and by logic, and `python research/_scaffold/check_scaffold.py` names
every file still carrying the quote-excluding capture.

A shared module under `research/` importable by every tree was the proposed
repair.  **It is declined, and the reason is the point**: a shared guard is a
single point of trust for eight independent pins.  Each tree's
`verify_sources.py` pins a *different* baseline commit, and a change that bent
one tree's guard would silently bend all eight.  The isolation is what the
copies buy, and the checklist above is not the cost of a missing abstraction —
it is the price of the isolation.

What was wanted from the repair is *visibility*, and that is what
`house_diff.py` gives.  It parses each copy, extracts the top-level
definitions, replaces every literal with a placeholder — so a tree's own
baseline, schema and module census never read as a difference — and reports
which trees agree with which on each definition's **logic**:

```
python research/house_diff.py --logic
```

It reads and changes nothing; a clean report is not a receipt, and it cannot
notice a defect all eight copies share.

**Its first run, 2026-09-09, found the drift it was built for.**  Eleven
definitions differ in logic, and one of them splits exactly along the line of
the three trees the receipts audit touched:

| definition | shape 1 | shape 2 |
|---|---|---|
| `runtime_errors` | `ignition`, `local_reuse`, `magnification`, `reachable`, `setting_translation` | `coherent_process_limits`, `record_reading`, `represented_execution` |

The five build their runtime census from the `derivation` modules alone; the
three build it from **every** module in `RUNTIME_PATHS`.  Today the difference
is **benign**, and for a stated reason: all five pin only `derivation` modules,
so the two readings agree on them.  It stops being benign the moment one of
those five pins a module of its own — a `translation`, an `execution` — at
which point its census would silently stop checking that module's origin.
Recorded rather than repaired, because repairing it would mean editing five
trees' pinned guards to no present effect; the condition under which it must
be repaired is now written down.
