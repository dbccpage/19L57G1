# Claim ledger — path_dependent_cost

One evidence class per row. Lean names live in `lean/PathDependentCost/`;
the pins are in `SOURCE_MANIFEST.json` and are checked by `verify_pins.py`;
every count is checked by `run_path_dependent.py` into
`receipts/path_dependent_cost.json`. `AuthorityEffect: None.`

| ID | class | statement | evidence |
|---|---|---|---|
| PD-1 | DEFINITION | A cost is **additive** when the price of a composite is the price of the first part plus the price of the second, charged where the second is applied. | `PathDependentCost.Additive` |
| PD-2 | DEFINITION | A cost is **exact** when some state functional has it as its difference. | `PathDependentCost.Exact` |
| PD-3 | PROVED_THEOREM | Additivity forces the empty response to cost nothing. Not a convention — apply the law to the empty response twice. | `PathDependentCost.additive_empty_zero` |
| PD-4 | PROVED_THEOREM | **Every additive cost is the summation of its own restriction to single moves.** So the space of additive costs is exactly the space of weightings, and a search over weightings misses nothing anyone could have proposed. | `PathDependentCost.additive_eq_sumEdges`, `sumEdges_additive` |
| PD-5 | PROVED_THEOREM | An exact cost gives two routes with the same endpoints the same total; so two routes with different totals refute exactness outright — no functional at all, not merely no obvious one. | `PathDependentCost.exact_agrees_on_two_routes`, `not_exact_of_routes_differ` |
| PD-6 | PROVED_THEOREM | **Directed closed walks are stationary** when a move never decreases the state and the order is antisymmetric: a walk returning to its start never left it. Stated over an abstract action with the order laws supplied as hypotheses. | `PathDependentCost.closed_directed_walk_is_stationary`, `le_actList` |
| PD-7 | METATHEORY | Consequence of PD-6: where admission only adds, path-dependence has exactly two sources — a move that changes nothing (waste) and two different routes to one state (order). Every table in this tree keeps them apart. | `STATUS.md`, `FW-DEGENERATE` |
| PD-8 | FINITE_COMPUTATION | The move graph is the estate's own: a node is a reachable state, an edge is exactly what `iter_cost1_items` offers there. No move is invented. | `movegraph.build`, `test_no_move_is_invented` |
| PD-9 | FINITE_COMPUTATION | At the declared depth three: 262 states, 638 moves, 2 components, cycle rank **378 = 232 waste + 146 order**. The rank strictly exceeds the self-loop count. Scope: this finite graph and nothing larger. | receipt `graph_by_depth`, `test_the_cycle_basis_has_the_right_size` |
| PD-10 | FINITE_COMPUTATION | At depth one the rank is **zero** — no closed walk of any kind — so a shallower rectangle would answer every circulation question vacuously. That is why the depth is three. | `test_depth_one_is_vacuous`, receipt `graph_by_depth` |
| PD-11 | FINITE_COMPUTATION | **770 commuting squares**: pairs of two-move routes leaving one state and landing on one state. | receipt `commuting_squares` |
| PD-12 | FINITE_COMPUTATION | Every self-loop in the rectangle is an instance repeat. No form item, datum item or rule item is ever offered as one by the sealed enumerator. | `test_self_loops_are_exactly_instance_repeats` |
| PD-13 | FINITE_COMPUTATION | Exactness is decided **twice** — by building the functional and by summing around a cycle basis — and the two agree on all nine candidates. Agreement is recorded per candidate, not assumed. | `exactness.decide`, `test_the_two_methods_agree_on_every_candidate` |
| PD-14 | FINITE_COMPUTATION | When exactness holds the walk *produces* the functional: for `reach` the recovered functional is total profile size on every edge. A positive answer is a witness. | `test_reach_is_exact_and_its_functional_is_the_profile_size` |
| PD-15 | FINITE_COMPUTATION, THE_HEADLINE | **`rule_span` is the object the preceding rung named**: additive by construction, reads the base (decided from evidence), not exact by both methods, **zero on all 232 waste cycles**, nonzero on 4 order cycles. Its reading: a commitment costs what it ranges over at the moment it is made. | receipt `candidates`, `test_rule_span_is_the_object_the_preceding_rung_named`, `test_rule_span_charges_nothing_for_a_wasted_move` |
| PD-16 | FINITE_COMPUTATION | The witness, readable: from one state to one state, commit-then-grow costs 2 and grow-then-commit costs 3. | receipt `candidates[rule_span].square_witness`, `test_the_square_witness_is_commit_early_against_commit_late` |
| PD-17 | PROVED_THEOREM | The same, abstractly and for every `n`: `commit_early` gives `n`, `commit_late` gives `n + 1`, the routes land on the same state, and the cost is therefore additive and not exact. | `Commit.routes_agree`, `commit_early`, `commit_late`, `span_prices_the_order`, `span_is_additive`, `span_is_not_exact` |
| PD-18 | PROVED_THEOREM | **The sealed item count cannot see the order**: on the very square where the span disagrees with itself, the count gives both routes the same total, because both use two moves. | `Commit.count_cannot_see_the_order` |
| PD-19 | FINITE_COMPUTATION | And computationally: `item_count` and `redundancy` are not exact but have **zero** circulation on every order cycle — they price waste and nothing else, which is the degenerate case `FW-DEGENERATE` names. | receipt `path_dependent_through_waste_only` |
