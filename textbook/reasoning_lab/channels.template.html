What survives the next process?

A process supplies output chances for each input. Combine two processes, then ask what can be learned by processing only a stored answer.

Supplied process models. No device trials, transmission speeds or heating were measured.

1. Does swapping the order preserve both rows?

Each table gives a chance for output 0 and output 1 at each input. The second process receives the first output and uses its stated row. “Same channel” here means matching output chances for both binary inputs; it does not mean the procedure histories are identical.

Predict before revealing.

Changing brackets keeps the execution order

For processes A, B, C, grouping A then B before C has the same conditional table as grouping B then C after A. That is associativity. Both procedures still run A, then B, then C. It does not permit swapping A and B. Each composition also assumes that the next row depends only on its supplied current input, with no hidden dependence on an earlier input or history.

2. Process only the stored answer

The recorder gives A and B answer 0, and C answer 1. The next function receives only that answer. It cannot inspect the original letter unless that access is separately added.

Predict before revealing.

One output preparation does not identify a process

Keeping and flipping a binary value are different row tables. Each sends an equal 0/1 input distribution to an equal 0/1 output distribution. The same aggregate output on that preparation therefore does not identify which process ran. Changing the preparation or retaining paired input/output records asks additional questions.

Tab to a wide table and use arrow keys to scroll. Keep equal chance tables, equal individual values, equal procedures and observed device behavior distinct.
