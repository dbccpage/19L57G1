# Source declarations, generated constants, and teaching coverage

AuthorityEffect: None. This is textbook audit apparatus. It changes no
sealed source, axiom allowance, historical inventory, or research claim.

## The distinction that matters to a reader

A source file can define a structure with several fields. Lean then
creates the structure's type, a constructor, field-access functions,
and supporting declarations. Counting those generated constants answers
a different question from counting source declaration heads. Neither
count tells us how many concepts a beginner understands.

For teaching, the next questions are: what does the definition mean,
what example distinguishes it from a nearby definition, what does its
theorem actually assume, and can a reader use it on a new example?
The [coverage matrix](../derivation_coverage.md) assigns places to look;
it does not discharge those questions.

## Source and method

The initial reconciliation used source commit
`40042318c3de2cfa04974efa4793b2e1f7e6335b`. The root and all 75 sealed
module files were hashed before and after the run. Their source-manifest
digest (SHA-256 of the sorted, compact JSON path-to-hash map) was
`d5ab25e8fdfc2fe7af07606b73a390ab4b364b3e87b886adaa3fc55ed8babfe9`.

[`refresh_inventory.py`](refresh_inventory.py) reuses the ledger check's
comment-aware source scanner and explicitly adds unnamed instance heads.
It imports the actual compiled module population through the existing
declaration-axiom census, extended with Lean's stored declaration ranges.
Each source candidate must resolve to **one same-module compiled name at
the same source line**, with the appropriate compiled kind. An unnamed
instance must resolve to an instance at that location. Missing, ambiguous,
or wrong-kind matches fail the reconciliation.

The refresh command now runs `lake build` itself before enumerating the
compiled environment. The initial run also followed a successful local
80-job build. No sealed declaration is edited or generated by this tool.

This remains a restricted source scanner, not a Lean parser or a proof
that every source command has been classified. Constructors, fields,
`deriving` commands, and generated supporting constants are outside its
source-head population. The separate compiled census includes the
constants those commands produce. Stored source locations corroborate
candidate identity; they do not certify the lesson's interpretation.

## Reproduction and regression evidence

From the repository root, with the pinned Lean toolchain available:

```powershell
python textbook/audit/refresh_inventory.py --out artifacts2/declaration_review/fresh
python textbook/checks/u00_declaration_inventory.py
```

The temporary-file directory must be writable and outside the repository,
as required by the existing compiled-census runner. The output folder
contains the build log, full compiled records, all 2,564 source-to-name
bindings, per-file source hashes, and log/source digests. It is local
receipt material, not a downloadable tracked artifact or a semantic
coverage certificate. The initial compiled log digest was
`014a6ef64f5570822421c5ba51e38f96a80a59f0a5b91c0de44c803a58805b71`.

Four regression tests reject nested-comment declarations, cover actual
false-match lines, retain unnamed instances, and reject same-name
matches at the wrong location, duplicate matches, and wrong compiled
kinds. They run through the textbook's ordinary Python-check discovery.

## What remains to teach and verify

The module table now uses these matched source-head counts and physical
line counts. Detailed declaration-placement tags and module-audit prose
still need semantic reconciliation. A helper may reasonably be omitted
from a beginner lesson; its omission needs a reason, rather than a claim
that every name must become a lesson. Conversely, a name in a code block
does not establish that its concept has been explained.

Unit 37 now introduces classification with two labelled dots, four
explicit patterns, the distinction between restriction and selection,
and a counterexample outside the restricted domain. Separate folded
practice answers test a changed example. Its formal source record and
existing executable checks remain available. The formal explanation also
corrects “twenty-four” pointwise cases to sixteen (four branches, four
ordered pairs per branch); three proof branches in the displayed excerpt
are abbreviated.

Neither the inventory repair nor these exercises establish novice
comprehension or retention. The broader research curriculum and reader
trials remain part of the active textbook goal.
