# Units 04–07: inputs, histories and erased results

Use the four Units in order. Explain each answer before opening the
[separate answers](state_history_answers.md). These are supplied model
questions, not measured reader outcomes.

1. Start with A already admitted. Replay an empty history, then separately
   replay a history containing only supply of B. What changes? Does an
   empty history require an empty starting ledger?
2. A separately written policy always chooses admission of the token P.
   Apply it twice from an empty Python ledger. How many entries and events
   are there? Did writing the policy require a seventh event kind?
3. In Unit 05's reading F, request separation of the initial mark and AB.
   Which positions name them? Can the same named request be made in L,
   where the initial mark is not admitted?
4. Start with AB admitted. Compare supply of AB with re-admission of AB.
   Do the resulting ledgers agree? Are the events equal? Which extra
   input lets a reader distinguish the two histories?
5. A raw token list already contains [A, A]. Re-admit A. Does this clean
   the list? What does its erased count measure?
6. Translate admission of A from two starting token stores: empty, and
   [A]. Which translated event is correct in each? Why would using the
   empty-base translation for [A] give a wrong counting-model result?
7. From the empty Lean token store, try admission of A, then impose the
   demand (0,1), then admission of B. Does the final admission rescue the
   replay? Where does the translated history stop?
8. A visitor list deduplicates equal printed names. Two visits have the
   same printed name. What establishes one list entry, and what additional
   evidence would be needed to conclude that the visits involved the same
   physical person? Do not invent an observation.

AuthorityEffect: None. Seven computational questions and one identity-evidence question.
