# 06. Carry the question list into reality

Suppose two keys give the same answers to your current checks: same
color, same approximate length. That supports a limited claim:
**these checks do not distinguish the keys**. It does not establish
that there is only one key or that both open the same lock.

The lab makes a similar distinction precise inside a declared model.
Equal profiles concern every question in that model's grammar.
Internal positions remain distinct. A new form can supply a new
question, and an added judgment can change an old answer.

The key story is an application proposal, not evidence that the lab
models keys correctly. A physical application would need to specify
how cards correspond to objects, how judgments correspond to checks,
and what observation could disagree with the prediction. It would
also need to justify any rule claimed to hold uniformly. Declaring
a rule in software is not discovering it by measurement.

Three limits matter when taking an intuition away:

- The item price is chosen. One uniform rule costs one item even
  though it changes many answers.
- A refusal within two additions is a bounded result. Lesson 03
  gives a reply beyond that bound.
- These selected computations do not prove the research's open
  general identification bounds or characterize every larger state.

Try the [practice](PRACTICE.md) on a different table before opening
the [answers](ANSWERS.md). Explain each prediction with an actual
question or an explicit limit; recognizing a familiar phrase is not
the same as being able to use it.
